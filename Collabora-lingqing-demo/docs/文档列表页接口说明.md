# 文档列表页接口说明

> 对应页面：`src/pages/DocumentsPage.vue`（路由 `/aidoc`）  
> 整理日期：2026-08-27  
> 现状：页面已画出完整交互，**数据全部写死在前端**，筛选、分页、复制、删除都在内存里完成，**还没有真正请求后端**。

本文只覆盖列表页本身。打开编辑器之后的 WOPI / Collabora 接口不在这里展开。

---

## 1. 页面在做什么

用户进入 `/aidoc` 后，主要完成四件事：

1. **按身份看文档**：我创建的 / 我参与的 / 全部 / 已归档。
2. **按条件找文档**：关键词、类型、状态、专业，再分页浏览。
3. **管理文档**：打开、复制、删除；勾选后可批量校验。
4. **新建或导入**：填名称、项目批次、编写目标，可挂参考资料，然后跳进编辑器。

后端需要按「当前登录用户」判定创建人、参与人、权限。列表页自己拿不到当前用户信息。

```text
分类 Tab 数量 ──► 统计接口
筛选 + 分页 ──► 列表接口
创建 / 导入 ──► 创建接口（可附带上传）
打开        ──► 打开会话接口（拿到 fileId / token 后跳 /aidoc/editor）
复制 / 删除 ──► 复制、删除接口
勾选批量校验 ──► 批量校验接口
下拉选项    ──► 字典接口（可选）
参考资料    ──► 文件上传接口
```

---

## 2. 和页面控件的对应关系

| 页面区域 | 现在怎么做 | 对接后需要的接口 |
| --- | --- | --- |
| 四个分类卡上的「N 份」 | 写死 `1 / 4 / 5 / 1` | 文档数量统计 |
| 表格数据 | 写死 5 条 `documents` | 文档分页列表 |
| 搜索框、类型、状态 | 前端 `filter` | 列表查询参数 |
| 「专业」下拉 | 有控件，**列表过滤没接上** | 列表增加 `major` 参数 |
| 分页 | 前端 `slice` | 列表的 `page` / `pageSize` / `total` |
| 「创建文档」抽屉 | 校验名称后直接跳编辑器 | 新建文档 |
| 「导入已有文档」 | 文案有，**没有选择源文件** | 导入文档（上传 DOCX） |
| 「添加资料」 | 只记下文件名，不上传 | 参考资料上传 |
| 「打开」 | 固定跳 `/aidoc/editor`，**不带文档 ID** | 打开编辑会话 |
| 「复制」 | `Date.now()` 造一条本地副本 | 复制文档 |
| 「删除」 | 从本地数组删掉 | 删除文档 |
| 「批量校验」 | 按钮有，**没有点击逻辑** | 批量校验 |

`loading` 已经预留，接接口后用来转表格 loading 即可。

## 3. 建议的统一约定

路径前缀建议：`/api/aidoc`。  
用户身份走登录态（Cookie / Token），不要前端传 `userId`。

建议响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

`code !== 0` 时前端提示 `message`。

列表里一条文档建议包含页面用到的全部字段：

```ts
interface DocumentListItem {
  id: string                 // 文档 ID，打开/复制/删除都用它
  name: string               // 文档名称
  description: string        // 名称列 hover 提示
  type: 'formal' | 'normal'  // 制式文档 / 普通文档
  typeLabel: string          // 「制式文档」等展示文案
  template: string           // 模板名称
  status: 'draft' | 'writing' | 'done'
  statusLabel: string        // 「草稿」/「编写中」/「已完成」
  version: string            // 如 V1.3
  snapshotCount: number      // 自动快照数
  milestoneCount: number     // 里程碑数
  major: string              // 专业：结构 / 工艺 / 质量
  owner: { id: string; name: string }
  members: Array<{
    id: string
    name: string
    role: 'owner' | 'editor' | 'viewer'
    roleLabel: string        // 拥有者 / 编辑者 / 阅读者
  }>
  updatedAt: string          // 建议 ISO8601，前端再格式化
  issueCount: number         // 校验问题数
  archived: boolean
  myRelation: 'created' | 'joined'  // 相对当前用户
}
```

表格「进展」列当前展示的是 `自动快照 4 · 里程碑 2`，用 `snapshotCount`、`milestoneCount` 拼即可。  
筛选里那个叫「进展」的下拉，实际筛的是 **文档状态**（草稿 / 编写中 / 已完成），不要和快照数混在一起。

## 4. 接口清单

下面 8 个接口按页面使用顺序排列。前 4 个是列表页能跑起来的最小集。

### 4.1 文档数量统计

页面四个分类卡各要一个数字，且 **不受当前筛选影响**（切 Tab 时筛选项会重置，但数量应始终是该分类下的总量）。

- **方法 / 路径**：`GET /api/aidoc/documents/stats`
- **何时调用**：进入页面；创建、复制、删除、归档成功后刷新
- **响应 `data`**：

```json
{
  "created": 1,
  "joined": 4,
  "all": 5,
  "archived": 1
}
```

含义与 Tab 一致：

| 字段 | Tab | 统计口径 |
| --- | --- | --- |
| `created` | 我创建的 | 当前用户是拥有者，且未归档 |
| `joined` | 我参与的 | 当前用户是编辑者或阅读者，且未归档 |
| `all` | 全部文档 | 当前用户有权限的未归档文档 |
| `archived` | 已归档 | 当前用户有权限的已归档文档 |

也可以把这 4 个数字塞进列表接口，但分类卡和表格筛选条件不同，**单独做统计更不容易算错**。

---

### 4.2 文档分页列表（核心）

表格、搜索、筛选、分页都走这一条。不要一次把全部文档拉到前端再切。

- **方法 / 路径**：`GET /api/aidoc/documents`
- **何时调用**：进入页面；切换 Tab；点「查询」；改下拉；翻页 / 改每页条数

**查询参数：**

| 参数 | 来源 | 说明 |
| --- | --- | --- |
| `scope` | 分类 Tab | `created` / `joined` / `all` / `archived`，默认 `created` |
| `keyword` | 搜索框 | 匹配文档名称；建议同时匹配模板名、负责人名（与现网搜索提示一致） |
| `type` | 类型下拉 | `all` / `formal` / `normal` |
| `status` | 「进展」下拉 | `all` / `draft` / `writing` / `done` |
| `major` | 专业下拉 | `all` / `结构` / `工艺` / `质量`，或后端自己的编码 |
| `page` | 分页 | 从 1 开始 |
| `pageSize` | 分页 | 10 / 20 / 30 / 40 / 50 |

`scope=archived` 只返回已归档；其余三个 Tab **排除**已归档。

**响应 `data`：**

```json
{
  "page": 1,
  "pageSize": 10,
  "total": 5,
  "list": [ { "...DocumentListItem" : true } ]
}
```

表格「序号」用 `(page - 1) * pageSize + index + 1` 在前端算，不必单独返回。

---

### 4.3 新建文档

抽屉选「新建文档」，填名称（必填）、项目/型号/批次、编写目标，可选参考资料，点「创建并进入编辑器」。

- **方法 / 路径**：`POST /api/aidoc/documents`
- **Content-Type**：`multipart/form-data`（有参考资料时）或 `application/json`（没有附件时）

**字段：**

| 字段 | 必填 | 对应表单项 |
| --- | --- | --- |
| `name` | 是 | 文档名称 |
| `project` | 否 | 项目 / 型号 / 批次 |
| `goal` | 否 | 编写目标 |
| `type` | 否 | 缺省可由后端按模板决定 |
| `templateId` | 否 | 当前抽屉还没选模板，可先不传 |
| `references` | 否 | 参考资料文件，多文件 |

**响应 `data`：** 新建结果 + 打开编辑器所需会话。

```json
{
  "id": "doc-1001",
  "name": "某型号结构件军检记录",
  "editor": {
    "fileId": "wopi-file-id",
    "accessToken": "...",
    "wopiSrc": "http://host.docker.internal:5174/wopi/files/...",
    "fileName": "某型号结构件军检记录.docx"
  }
}
```

前端拿到 `id` 后跳转：`/aidoc/editor?id=doc-1001`。  
`editor` 也可以创建成功后再调「打开编辑会话」拿，但用户点完会立刻进编辑器，**创建接口直接带回会话能少一次等待**。

---

### 4.4 导入已有文档

抽屉选「导入已有文档」，点「导入并进入编辑器」。页面现在没有源文件选择框，对接时需要补一个上传控件；接口仍应先定下来。

- **方法 / 路径**：`POST /api/aidoc/documents/import`
- **Content-Type**：`multipart/form-data`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 源文档，建议仅 `.docx` |
| `name` | 否 | 不传则用文件名 |
| `project` | 否 | 同新建 |
| `goal` | 否 | 同新建 |
| `references` | 否 | 参考资料 |

响应结构与「新建文档」相同，同样要能立刻进编辑器。

现有 Demo 里的 `POST /api/collabora/files` 只解决「上传一个临时 DOCX 给 Collabora」，**没有文档台账、权限、分类**，不能替代本接口。导入成功后，应由业务侧落一条文档记录，再生成 WOPI 文件。

---

### 4.5 打开编辑会话

行内「打开」。现在链接是死的 `/aidoc/editor`，接上后必须带文档 ID。

- **方法 / 路径**：`POST /api/aidoc/documents/{id}/editor-session`
- **何时调用**：点击「打开」；若创建/导入没带回 `editor`，进入编辑器页时补调

**响应 `data`：** 与现有 `WopiLaunchInfo` 对齐，编辑器页可直接喂给 iframe。

```json
{
  "fileId": "wopi-file-id",
  "fileName": "工艺评审检查清单.docx",
  "accessToken": "...",
  "wopiSrc": "http://host.docker.internal:5174/wopi/files/...",
  "downloadUrl": "/api/collabora/files/.../download?access_token=...",
  "version": 3,
  "updatedAt": "2026-07-10T09:12:00.000Z"
}
```

权限不够、已归档只读等，用 `code` / `message` 说明，前端不要进编辑器。

---

### 4.6 复制文档

行内「复制」。本地逻辑是：新 ID、名称加「（副本）」、状态改成草稿、成员拷一份。

- **方法 / 路径**：`POST /api/aidoc/documents/{id}/copy`
- **请求体**：可空。若要允许改名，可传 `{ "name": "xxx（副本）" }`
- **响应 `data`：** 一条 `DocumentListItem`（新文档）

成功后刷新当前列表和 Tab 数量。是否马上打开编辑器，产品未要求，保持「复制后仍停在列表」即可。

---

### 4.7 删除文档

行内「删除」。建议二次确认后再调。

- **方法 / 路径**：`DELETE /api/aidoc/documents/{id}`
- **响应 `data`：** `{ "id": "doc-1001" }`

权限：通常仅拥有者可删。失败时返回明确文案。  
成功后扣减当前页；若本页删空，前端把页码回退一页再拉列表。

---

### 4.8 批量校验

多选后出现「批量校验 (N)」，目前没有处理函数。

- **方法 / 路径**：`POST /api/aidoc/documents/validate`
- **请求体：**

```json
{
  "ids": ["doc-1001", "doc-1002"]
}
```

**响应 `data` 建议：**

```json
{
  "taskId": "validate-88",
  "total": 2,
  "accepted": 2,
  "rejected": []
}
```

校验是异步还是同步，列表页只需要两件事：

1. 提交成功给出提示；
2. 结束后刷新列表，更新「校验问题」列的 `issueCount`。

若校验很慢，用 `taskId` 再查进度；若很快，本接口直接返回每篇 `issueCount` 也可以。

## 5. 建议有、但不是第一批的接口

这些能提升体验，没有也不阻塞把列表跑通。

| 接口 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/aidoc/dictionaries` | 类型 / 状态 / 专业 / 模板下拉 | 现在写死在页面里。专业、模板以后会变，适合接口下发 |
| `POST /api/aidoc/uploads` | 参考资料先传后绑定 | 抽屉里「添加资料」现在只存文件名。大文件建议先上传拿 `fileId`，创建时只传 ID 列表 |
| `GET /api/aidoc/templates` | 创建时选模板 | 表格有「模板」列，创建抽屉还没选模板 |
| `POST /api/aidoc/documents/{id}/archive` | 归档 / 取消归档 | 有「已归档」Tab，页面还没有归档按钮 |

当前用户信息如果外壳已经注入，列表页可以不单独调「谁在登录」；否则需要 `GET /api/me`。

## 6. 调用时机（按用户操作）

```text
进入 /aidoc
  ├─ GET /documents/stats
  └─ GET /documents?scope=created&page=1&pageSize=10

点某个分类卡
  └─ GET /documents?scope=xxx&（筛选项重置）

点查询 / 改下拉 / 翻页
  └─ GET /documents?（当前筛选 + 分页）

点创建并进入编辑器
  └─ POST /documents  →  跳 /aidoc/editor?id=

点导入并进入编辑器
  └─ POST /documents/import  →  跳 /aidoc/editor?id=

点打开
  └─ POST /documents/{id}/editor-session  →  跳编辑器

点复制
  └─ POST /documents/{id}/copy  →  刷新列表 + stats

点删除
  └─ DELETE /documents/{id}  →  刷新列表 + stats

点批量校验
  └─ POST /documents/validate  →  完成后刷新列表
```

## 7. 和现有 Collabora 接口的边界

| 能力 | 现有接口 | 列表页能不能直接用 |
| --- | --- | --- |
| 上传临时 DOCX 并打开 Collabora | `POST /api/collabora/files` | 不能当文档台账。没有分类、成员、状态 |
| 查保存版本 / 下载 | `GET /api/collabora/files/:id/status` | 编辑器页用，列表页不用 |
| WOPI CheckFileInfo / GetFile / PutFile | `/wopi/files/:id` | Collabora 自己调，列表页不调 |

列表页先走 **业务文档接口**；真正进编辑器时，再由「打开编辑会话」去换 WOPI `fileId + accessToken`。两边 ID 建议分开：业务 `document.id` 稳定不变，WOPI `fileId` 可以随文件存储变化。

---

## 8. 对接时要注意的页面缺口

这些不是接口设计错误，是页面还没做完，后端按「做完后会长成这样」来备即可：

1. **打开必须带 ID**，否则永远打开同一份空编辑器。
2. **专业筛选**前端还没参与过滤，接口仍应支持 `major`，避免以后再改协议。
3. **导入**缺少源文件上传控件，接口要按有 `file` 来设计。
4. **批量校验**没有二次确认、没有结果展示，接口先保证能提交、能更新 `issueCount`。
5. **参考资料**需要真实上传，不能只传文件名。
6. 删除、批量操作建议后端做权限校验：阅读者不能删，已归档是否允许编辑要产品定。

---

## 9. 建议落地顺序

1. **统计 + 列表**：四个 Tab 和表格能看到真数据。  
2. **打开会话**：列表能进对应文档的编辑器。  
3. **新建 / 导入**：抽屉走通，并能跳编辑器。  
4. **复制 / 删除**：行内操作接上。  
5. **批量校验、参考资料上传、字典**：按产品优先级补。
